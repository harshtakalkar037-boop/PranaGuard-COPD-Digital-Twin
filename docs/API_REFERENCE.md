# API reference

The current route-by-route server authorization requirements are in [ROUTE_PERMISSION_MATRIX.md](ROUTE_PERMISSION_MATRIX.md); original and enhanced schemas are documented in [API.md](API.md) and [enhanced/API_ENHANCED.md](enhanced/API_ENHANCED.md). `/openapi.json` provides the generated schema. In secure mode, doctor `/api/overview` and `/api/patients` return only assigned original synthetic twins; their aggregates, trends and open-alert counts use the same population. Empty assignment returns empty data. Global validation endpoints require all original twins, while unscoped replay and device operations remain under the restrictive whole-workspace gate. Patient data is accessible only under portal ownership or assignment checks. Unsafe legacy mode is isolated and must not be network-exposed.

A doctor may `POST /api/portal/patients/{pid}/reviews/{review_id}/complete-followup` with `notes` (1–2000 characters) for an assigned synthetic patient's open dated follow-up. The original review is preserved; a separate private completion record and audit event are inserted atomically. Missing/unassigned records return 404, invalid requests 422, and already-completed or non-dated follow-ups 409. Completion removes the item from the due queue and summary. It does not notify the patient.

`POST /api/portal/login` returns 429 with `Retry-After` when a case-insensitive username (whether or not it exists) has five failures in the preceding 15-minute fixed window. A successful login or trusted local password reset clears its window. This is not IP or distributed rate limiting and may allow targeted account lockout.

`GET /api/portal/care-queue` requires a doctor session and scopes all results and the total to currently assigned, explicitly synthetic records. It accepts `limit` (1–200, default 200), `offset` (default 0), `kind` (`all`, `checkin`, `sputum`, `upload`, `daily`, `followup`) and `order` (`newest`, `oldest`). It returns `items`, `limit`, `offset`, `total`, `has_more` and a non-clinical notice. Open check-ins/uploads include Pending Review, Under Review and Follow-up Required; sputum/daily entries include Pending Review; dated uncompleted follow-ups appear when due. A related submission and follow-up can appear separately. Count and page share a read snapshot, but data changes between requests can shift offset-based pages. Sorting is by recorded timestamp/date with deterministic tie-breakers, not clinical urgency.
